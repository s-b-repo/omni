# Negative results — the closed-experiment ledger

Four repositories, written separately, with a shared habit: an idea gets
measured, the measurement comes out negative or uninteresting, the finding is
written down, and then somebody has the same idea eighteen months later and
spends a week rediscovering it. Re-running a settled experiment is the most
expensive habit in this family, because it costs the week *and* produces a second,
slightly different number that then has to be reconciled with the first.

This file is the machine-checkable list of those experiments.

**The rule:** *a closed result is closed until its reopening condition is met and
measured, not until someone has an idea.* The last column is the point of the
document. A result with no reopening condition is not a closed result; it is a
rumour with a citation, and the next reader cannot tell the difference. So
`scripts/verify-cross-repo.sh` check 6 fails on any row whose reopening cell is
empty — the emptiness is the defect, not the result.

Every entry is somebody else's measurement, quoted rather than re-derived. The
"Reopen only if" column says what would have to be *shown*, never what would have
to be *thought*. An entry that said "a better implementation might win" would
reopen on every idea.

## Why the citations are checked

A citation that has rotted is worse than no citation, because it reads as
evidence. Every source in this file is a backticked absolute path with a line
number, and `scripts/verify-cross-repo.sh --strict` fails when any cited file no
longer exists or when a cited line has fallen outside the file's current length.
It does not check that the line still says what the entry claims — that is a
reading, and a reading belongs to a reviewer.

It also fails on a row whose *Reopen only if* cell is empty, because that cell is
the whole reason this document exists. It fails on a row that is not the
five-column shape, because the readers key off that shape, and on a duplicated
ID, because two results under one name cannot be told apart later.

## How to add an entry

1. Find the measurement, not the idea. If nobody ran it, it is not here.
2. Copy the exact figure and its units out of the source. Do not round, do not
   paraphrase a number into a stronger or weaker one, and do not carry a figure
   across models or corpora without saying so.
3. Cite the file **and the line**, in backticks, as an absolute path. The gate
   resolves it; a bare filename does not.
4. Write the reopening condition as *what would have to be measured*. If you
   cannot write it, the experiment is not closed — it is unfinished, and it
   belongs in a TODO, not here.
5. If the entry contradicts a claim made in prose anywhere in these four repos,
   say which prose, so the contradiction is visible rather than latent.
